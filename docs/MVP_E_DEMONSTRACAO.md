# MVP ou protótipo parcial — evidências e roteiro

O material didático de 11/10 exige uma versão mínima **funcional** para apresentar ao cliente. Este repositório contém a preparação documental da demonstração; não contém código de produto nem prova de um MVP funcionando. A equipe precisa fornecer a versão executável e o registro abaixo antes de apresentar este item como cumprido.

## Evidências a anexar

| Campo | Valor atual |
|---|---|
| Repositório/branch ou PR do produto | Pendente de informação da equipe |
| URL de homologação ou instruções de execução | Pendente |
| Versão ou commit demonstrado | Pendente |
| Contas de teste fictícias, se necessárias | Pendente; não registrar senhas |
| Captura ou vídeo do Orbitinho | Pendente |
| Captura ou vídeo da página pública | Pendente |
| Resultado da revisão de privacidade/autorização | Pendente |
| Data, apresentador e aceite do cliente | Pendente |

## Roteiro curto para a revisão

1. Mostrar o estado do produto e declarar quais fluxos estão realmente disponíveis.
2. Fazer uma pergunta pública sobre a plataforma ao Orbitinho; verificar se a resposta corresponde à fonte aprovada.
3. Pedir um destino por texto e, se houver suporte, por voz; observar a rota aberta ou o tratamento seguro de ambiguidade.
4. Abrir uma Espaçonave pública com dados autorizados; mostrar capa, perfil e trabalhos disponíveis.
5. Abrir um slug inexistente ou privado e verificar que não mostra dados internos.
6. Encerrar com as pendências, o backlog atualizado e o que cabe até a entrega final.

Use dados fictícios em demonstrações públicas. Se um fluxo não funcionar, marque-o como pendente em [Funcionalidades e aceite](FUNCIONALIDADES_E_ACEITE.md) e no [backlog](BACKLOG_ENTREGAVEL_2.md), sem substituir execução por mock estático.
